# Add acceptance criteria to all Sprint 1 tickets

## Description

In Agile, acceptance criteria refer to a set of predefined requirements that must be met to mark a user story complete.

These requirements will relate very closely to what you decide upon in your **Definition of Done,** with some additions to make them specific to each ticket.

For example:

- You paired or mobbed on the work
- The new feature / code works as expected, and was tested by someone else
- A Git Branch was created for the work, a Pull Request was raised for review, the PR was merged when done, the branch was deleted after the ticket was complete
- Logging was added to your new unctions
- Unit tests were done for all new code, and run by someone else to confirm
- All new features were tested by the team
- The main README.md in the repo was updated with any new instructions or information

## User Story

**As a member** of the development team
**I want** acceptance criteria on user stories to be part of our ways of working
**So that** all team members have a shared understanding of the work to be delivered as part of the current sprint
